# SPEC.md — Спецификация: AI-контур разработки проектов

> Источник истины о том, ЧТО строим. Приоритет над всеми документами (§0 правил).

---

## 1. Назначение

Приложение — **AI-контур разработки проектов**: из ТЗ целого проекта оно ведёт всю разработку до работающего продукта, управляя Claude Code (разработчик) и Codex (аудитор), принудительно проводя каждую задачу через защиту качества.

**Архитектор** (человек) утверждает архитектуру и принимает этапы по поведению, не читая код.

## 2. Стек приложения

- **Язык:** Python ≥3.11
- **Движок:** Claude Agent SDK (хуки = принуждение, субагенты = раздельные контексты/модели, учёт токенов)
- **Целевой проект:** переменный стек, читается из конфига

## 3. Ключевые компоненты (v1)

### 3.1. Задачный цикл с принуждением
- Критерии и тест-план ДО реализации
- Регрессионная защита (тесты + покрытие)
- Независимый аудит (Codex, адверсариально)
- Mutation testing на критичных модулях
- Принуждение через хуки: нет «готово» без тест-плана + зелёных тестов + approve

### 3.2. Проектный уровень
- Декомпозиция ТЗ → архитектура + задачи + граф зависимостей + этапы
- Общая база знаний (SPEC, ADR, контракты)
- Сборка и E2E на границах этапов
- Явная приёмка каждого этапа Архитектором

### 3.3. Наблюдательная панель
- Статусы задач и этапов
- Живые логи разработчика и аудитора
- Счётчик стоимости (токены → USD)
- Контрольные точки (утверждение, приёмка)

## 4. Бизнес-инварианты

1. **INV-1:** Задача не может перейти в статус `PR_READY` без зелёных тестов И approve аудитора
2. **INV-2:** Разработчик не коммитит в `main` — только feature-ветка → PR
3. **INV-3:** Аудитор не видит рассуждения разработчика — только дифф, критерии, результаты тестов
4. **INV-4:** Этап не переходит в `ACCEPTED` без явного утверждения Архитектора
5. **INV-5:** Бюджет задачи/проекта не может быть превышен без явного расширения

## 5. Порядок реализации

1. ✅ Строгий контур GitHub (branch protection + CI + документы)
2. Адаптер исполнителя на Agent SDK + evidence pack + учёт стоимости
3. State machine задачного цикла + критерии-вперёд + mutation
4. Проектный уровень (декомпозиция, граф, сборка, приёмка)
5. Наблюдательная панель

## 7. Что НЕ делаем (v1)

- Многопользовательскость
- Параллельные проекты
- GUI-редактирование кода через панель
- Замена независимого аудита самопроверкой
